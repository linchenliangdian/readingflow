# Reading flow 2.2.4

A tool for better reading and note-taking

在 Zotero 的右侧栏写一篇连续的阅读笔记。正文使用 **Zotero 原生笔记编辑器**；顶部只保留倒计时、可折叠检视清单与黑白金字塔。适配 Zotero 9.0.x 与 10.0.x。

## 安装与打开

1. 从 [GitHub Releases](https://github.com/linchenliangdian/readingflow/releases/latest) 下载 `reading-flow-2.2.4.xpi`。Zotero → **工具 → 插件** → 齿轮 → **从文件安装插件**，选择下载的 XPI。同一插件 ID 会替换旧版。安装后重启 Zotero，再打开阅读台。
2. 在文献库中选中文献或独立笔记，也可在 Zotero 标签页打开文献的 PDF。在右侧竖排图标中点击小金字塔 **阅读台**；也可右键选中的条目 → 阅读台。
3. 在侧栏直接写笔记。点击其他侧栏图标，可以回到 Zotero 信息、笔记或 Better Notes 面板。

**已有 2.1.0 或更早版本的设备，需要手动安装一次 2.2.4。** 从这一版起，插件通过本仓库的 GitHub Releases 提供更新，后续更新跟随 Zotero 插件管理器中的自动更新设置；关闭自动更新时，可在插件管理器中手动检查更新。各设备需分别安装插件，Zotero 的文献数据同步不会安装插件。

首次为文献打开阅读台，会在文献下创建一篇普通子笔记，不自动添加标签。以后通过笔记的固定 Key 继续使用同一篇笔记，正文由 Zotero 自动保存，可以使用原有的加粗、标题、列表、引用及注释操作。提纲可以自由修改或删除。打开旧版阅读笔记时，会在确认并保存关联后移除旧版自动添加的 `Reading Flow` 和 `Reading Flow · sidebar` 标签，保留你自己的其他标签；独立笔记的标签不作修改。

为独立笔记打开阅读台时，侧栏直接编辑这篇笔记，原正文保留，不另建正文笔记，也不为原笔记添加标签。你可以使用倒计时、金字塔、文字加粗及背景／冲突注释；点击 **插入笔记**，图片会插入这篇独立笔记的光标位置。可编辑的金字塔数据保存在同一文献库的“Reading flow 数据”条目下。选中文献下的子笔记时，仍按其所属文献打开阅读台。

也可以在 PDF 侧栏点击 **＋ → 添加独立笔记**，保持这篇笔记的编辑状态，再点击阅读台的小金字塔。倒计时和金字塔属于这篇独立笔记，插入的图片也写入同一篇笔记；尚未保存的新笔记会先保存，再打开阅读台。

## 一次阅读

- **10 分钟**：开始检视阅读。可展开标题、目录、摘要、关键句、结论、参考文献清单；“检视完成”由你勾选。分类可以记录在自己的书目表中。
- **20 分钟**：开始另一段专注练习，在正文理解术语、复述命题、重建论证；需要时展开金字塔。
- **正文提纲**：主题与结构 → 术语与命题 → 批评性判断。包括作者的解答、未解决的问题，以及自己的判断和依据。

倒计时可以暂停、继续与重置。到点只提醒，不限制编辑，也不自动认定分析阅读已经完成。直接关闭运行中的计时器，计时仍按实际截止时刻继续；暂停后关闭则保持剩余时间。

## 金字塔

点击工具栏的小金字塔展开。最上层只有一个可换行的文本框，记录疑问与回答；下层记录论点及其理由。直接在黑色方框里写字，可以继续添加子节点、同级节点，调整同层顺序。2.0.3 将旧顶层的“科学问题”和“核心回答”内容按原顺序合并保留；工具栏、侧栏和插件管理器使用同一个灰阶小金字塔图标。

在“疑问／回答”、下层节点或“背景／冲突”框中选中文字，点击 **B** 或按 **Ctrl+B** 加粗；再次操作可取消加粗。文字及其局部加粗格式会随工具草稿、跨设备同步和 JSON 备份保留，也会出现在插入正文的金字塔图片中。

在 **B** 旁边选择 **字号**，可为整张金字塔设置 10–32 的字号。字号同时作用于节点文字、背景／冲突注释及新生成的图片，随这篇笔记保存、同步和 JSON 备份保留；调大后图片会重新换行并增加方框高度。已插入正文的图片是一份快照，调整字号后需再次点击 **插入笔记** 生成新版图片。

点击 **背景／冲突**，在顶层“疑问／回答”框旁展开注释区，记录研究背景和引出问题的冲突。注释区与顶层框同宽，比下层论点框更宽，便于横向书写。顶层仍只有一个“疑问／回答”框；这些注释随草稿保存，并随金字塔一起插入笔记。收起注释区不会删除内容。

2.0.1 修复了展开后区域不断缩小，以及缩小 PDF 窗口后正文超出可见范围的问题。金字塔与正文共用侧栏空间，窗口较小时可在金字塔区域内滚动；收起检视清单或备份菜单可腾出更多编辑空间。

拖动金字塔与正文之间的分隔线，上下调整金字塔的显示高度；选中分隔线后也可用上下方向键调整。双击分隔线或按 **Home** 恢复自动高度。手动高度会在切换笔记或重新打开窗口后保留，正文仍留有可编辑的空间。高度属于本机界面偏好，不随金字塔数据同步。

每个方框尽量写成完整判断句。上层概括下层，下层回答上层引发的疑问；同组思想的分类与顺序要有逻辑依据。参见[方法依据](METHOD.md)。

点击 **插入笔记**，把当前金字塔作为黑白 PNG 图片插入正文的光标位置；原有文字会保留。插件等到图片附件与正文实际保存后才提示插入成功。图片是一份当时的快照，继续修改方框后，需要再次插入新的图；可编辑的树结构单独保存并同步。

## 保存、迁移与备份

**2.2.4 修复了倒计时结束后金字塔被误判为同步数据损坏的问题。** 读取时先校验保存的原始内容，再更新倒计时显示；完整的旧数据文件可直接恢复，不需要重建金字塔。术语的内部编号也会在重复读取时保持稳定。各设备均建议更新。

**2.2.0 将同步数据集中到“Reading flow 数据”专用条目下的 JSON 附件中。** 可编辑的树、局部加粗、字号、背景／冲突、检视清单及阅读进度都在这些文件中；新保存的数据不再创建普通数据笔记，也不会占据 PDF 阅读侧栏的“所有笔记”列表。每篇文献和独立笔记仍有各自的金字塔。正文继续由原生笔记编辑器保存，迁移不会重写正文或已插入的 PNG。

每个文献库使用专用数据条目集中收纳。条目下可能有多个 JSON 文件：每次插件启动使用独立写入文件，保留其他设备或历史启动创建的文件，避免离线修改或复制配置后互相覆盖。请保留由插件管理的数据条目及附件；它们共同保存可编辑金字塔和冲突版本。

**2.2.3 修复了删除内部标签后无法打开金字塔的问题。** 数据识别改用专用条目的固定标记、存储附件信息和 JSON 内容校验，不再依赖标签，也不再给数据条目或附件自动添加标签。旧版已去掉标签的数据文件可以继续读取；各设备都应升级到 2.2.4 或更高版本。

**可编辑金字塔和正文 PNG 都需要 Zotero 文件同步。** JSON 使用 Zotero 存储附件，可通过 Zotero Storage 或适用的 WebDAV 文件同步传输；仅完成条目数据同步不足以下载文件。各设备需升级到 2.2.4 或更高版本，使用同一账户同步同一个文献库。保留“按需下载”设置也可以，打开金字塔时插件会请求下载缺失的数据附件，不会改变 PDF 下载偏好。参见 [Zotero 文件同步设置](https://www.zotero.org/support/preferences/sync)。

旧版迁移按以下顺序进行：

1. **先在保有旧金字塔的电脑上安装并运行 2.2.4**。插件读取旧数据笔记及本机旧 JSON，将完整、可验证的版本写入专用条目下的数据文件。
2. 完成 Zotero 数据和文件同步。插件核实对应 JSON 的实际内容与已上传校验值一致后，才将已经完整迁移的旧数据笔记移入 Zotero 回收站；不会永久删除。
3. 在其他桌面设备上安装新版，同步同一文献库并下载数据附件，再打开阅读台。正文笔记及图片继续按 Zotero 原有方式使用。

尚未上传、缺少分块、损坏、没有可验证版本头的旧分块，或只读文献库中的数据，会保留原样。因此升级后旧数据笔记可能暂时仍可见；完成文件同步后插件会继续检查迁移。缺失或损坏的文件不会被当作空白金字塔覆盖。

本机 `reading-flow/文献库ID-条目Key.json` 继续作为缓存与本地备份保留；迁移后通过 `readingFlowSync` 元数据字段记录同步状态。只在新电脑安装新版，无法取回仍只存在旧电脑 JSON 中、尚未迁移的数据。

不同设备的文件保留各自的版本，并用向量时钟记录先后关系。遇到不同设备分别修改产生的冲突时，阅读台会保留各分支，先让你切换预览，再点击 **采用此版本** 继续编辑；原冲突分支仍保留，不会因选择而删除。

工具栏 **…** 中可导出／导入当前文献或独立笔记的 JSON 工具备份；独立笔记的导出文件名使用笔记标题。正文请使用 Zotero 原有备份方式；JSON 不是正文与图片的完整备份。导入工具备份不会改写正文。

**2.0.2 修复侧栏打开时的关联报错。** 如果原阅读笔记已在回收站或已移除，插件先备份原工具草稿，再重新关联文献下唯一可用的专属阅读笔记；没有可确定的笔记时则创建一篇新笔记。倒计时、检视清单和可编辑金字塔保留，回收站中的原笔记保持原样。新笔记不会自动复制回收站中的正文；原正文仍可在 Zotero 回收站查找。已有笔记仅移除标签时，仍继续使用原笔记。

重新关联前的备份位于同一 `reading-flow` 目录，文件名为 `文献库ID-条目Key.before-note-relink-时间戳-随机字符.json`。备份保留原 JSON 文件的完整内容。若笔记已移动到另一篇文献，插件会提示检查关联，避免将正文写入错误文献。

第一次打开旧版文献时，读取原有 v1 草稿，将问题、结构、术语、金字塔、出处与下一步写入新的原生阅读笔记。以前导出的快照和你自己的其他笔记保留。旧的五项检视清单保留在草稿的 `legacyChecklist` 中，按可确定的含义迁移到新版六项清单；没有检查过的项目不会被自动勾选。

只读文献库不会新建或改写笔记。若已有阅读笔记则以只读模式显示，计时草稿仍可在本机保留。

插件更新使用 GitHub Releases 的 `updates.json`，其中记录版本、Zotero 兼容范围、XPI 下载地址和 SHA-256 校验值。更新入口固定，安装包地址随版本变化；笔记、文献库及本机缓存不发布到 GitHub。

## 开发与验证

```sh
node --test tests/*.test.cjs
python build.py
```

可选的工具栏界面检查使用 Playwright：安装 `playwright` 并运行 `npx playwright install chromium` 后，执行 `node tests/ui.smoke.cjs`。已有系统 Chrome 时也可使用；`PLAYWRIGHT_MODULE` 和 `CHROME_BINARY` 可分别指定模块与浏览器路径。

`bootstrap.js` 负责生命周期，`integration.js` 负责侧栏、原生笔记与文件边界，`sync.js` 负责版本冲突及旧数据笔记迁移，`file-sync.js` 负责集中存储附件、文件校验与上传确认，`core.js` 负责计时、校验、迁移提纲和图形生成，`app.xhtml/app.js/style.css` 负责紧凑工具栏与金字塔。

实机测试使用项目内独立 profile 和 data 目录，避免修改正式文献库。本机测试产物、临时文献库及历史验证记录不纳入源码仓库。同步实现经过本地双设备模拟与隔离 Zotero 验证；这不等同于真实账户的云端双机实测。

## 发布新版本

1. 同时提升 `manifest.json` 与 `package.json` 的版本号，并把 `content/app.xhtml` 中样式与脚本 URL 的 `?v=` 更新为相同版本；构建会校验这三个资源的版本，避免更新后复用旧缓存。使用递增的 `X.Y.Z` 稳定版本，保持插件 ID `reading-flow@local` 不变。
2. 运行测试与构建，提交源码，再创建并推送对应标签 `vX.Y.Z`。例如版本 `2.2.4` 对应标签 `v2.2.4`。
3. 标签触发 GitHub Actions 工作流。工作流校验版本与标签、运行测试、构建 XPI、生成带 SHA-256 的更新清单，然后发布 GitHub Release 的 XPI、`updates.json` 与校验文件。

本地可先生成发布文件而不上传：

```sh
python build.py
python scripts/release.py --repository linchenliangdian/readingflow --tag v2.2.4 --xpi output/reading-flow-2.2.4.xpi
```

同一版本的已发布安装包不应覆盖；修复后提升版本并创建新标签。仓库需公开，以便 Zotero 无需 GitHub 登录即可读取更新清单和安装包。

也可直接在 GitHub 提交发布请求，无需本机安装 GitHub CLI：先将新版本源码提交到仓库并取得完整 commit SHA，再修改 `.github/release-request.json` 中的 `version` 与 `commit`，提交到 `main`。`commit` 使用待发布源码的完整 40 位 SHA。工作流会检出这一确切提交，测试与构建通过后创建指向它的版本标签并完整发布；已有同名标签指向其他提交时会停止，既有发布文件不会覆盖。失败后可在 Actions 的 **Publish requested version** 中重新运行；请求中的版本必须与所指提交的 `manifest.json`、`package.json` 一致。
